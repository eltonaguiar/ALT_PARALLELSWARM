Summary of Properties related to remediation of duplicate CIs These properties allow ServiceNow administrators to configure how duplicate Configuration Items (CIs) are remediated when using the Duplicate CI Remediator or the De-duplication dashboard in CMDB Workspace. Proper configuration helps optimize performance and control the remediation process to suit your organization's needs. Show full answer Show less Key Properties and Their Practical Use Field Length Limit (glide.duplicateciremediator.max.fieldlength) : Sets the maximum attribute size (default 4000 characters) considered during deduplication tasks. Attributes exceeding this length are excluded from key remediation steps, helping maintain performance efficiency. Related Items Blacklist (glide.duplicateciremediator.relateditemsblacklist) : Defines a comma-separated list of related tables and reference columns excluded from merging during remediation. This prevents merging sensitive or irrelevant related records, preserving data integrity. Maximum Duplicate CIs Threshold (glide.duplicateciremediator.max.cis) : Limits the number of duplicate CIs supported for reconciliation in remediation tasks, defaulting to 1000 with a hard cap at 5000. This ensures system performance remains stable when handling large volumes. Dry Run Mode (glide.duplicateciremediator.dryrun) : When enabled (true), allows testing remediation actions without applying changes to the CMDB. This provides a safe way to review intended updates before actual execution. Restricted Mode (glide.duplicateciremediator.enablerestrictedmode) : Enables a restricted remediation mode that limits the use of related items in deduplication. This mode allows blocked remediations to proceed with controlled handling of related records, enhancing flexibility in complex scenarios. Key Outcomes Admins can tailor duplicate CI remediation based on attribute sizes and related data considerations to optimize performance and accuracy. Limits on the number of duplicates handled ensure system stability during remediation operations involving large datasets. Dry run capability offers a risk-free way to validate remediation plans before committing changes. Restricted mode provides an alternative remediation path when standard processes encounter blocking issues due to related items. Note: These properties require the admin role for viewing and editing. Adjusting these settings should be done cautiously, especially the field length and maximum duplicates thresholds, as they directly impact remediation performance.
