Summary of Properties related to remediation of duplicate CIs

This content explains configuration properties that control how the remediation of duplicate Configuration Items (CIs) is handled in ServiceNow’s Duplicate CI Remediator and the De-duplication Dashboard within CMDB Workspace.
These properties require thesncmdbadminoradminrole to view or edit, allowing you to tailor de-duplication tasks to your CMDB environment while balancing performance and accuracy.

Key Properties and Their Functions

 glide.duplicateciremediator.max.fieldlength: Sets the maximum attribute length (default 4000) considered during remediation. Attributes exceeding this length are excluded from key remediation steps to optimize performance. Data exceeding this length is truncated if the maxlength equals this property’s value.
 glide.duplicateciremediator.relateditemsblacklist: Defines a comma-separated list of related tables and reference columns excluded from merging during remediation, preventing unintended updates to sensitive or critical related records.
 glide.duplicateciremediator.max.cis: Sets a threshold (default 1000, max 5000) for the number of duplicate CIs where reconciliation support is limited, ensuring system stability during large remediation tasks.
 glide.duplicateciremediator.dryrun: When true, enables a test run mode where no actual updates occur, but change details are logged as work notes. This helps validate remediation plans before execution (default is false, meaning updates are performed).
 glide.duplicateciremediator.enablerestrictedmode: Enables a restricted remediation mode that limits use of related items and allows blocked remediations to proceed. This is useful in complex environments where related item updates can cause issues.
 glide.duplicateciremediator.mergerelateditemsenhanced: When true (default), allows ignoring database errors and disabling workflows/business rules on related tables during remediation. This prevents workflow-induced failures and ensures remediation completion.

Why This Matters

Configuring these properties lets you control the behavior and performance of duplicate CI remediation to fit your organization’s unique CMDB scale and complexity. Proper settings help prevent performance bottlenecks, avoid unwanted updates to related records, and enable safe testing of remediation plans before applying changes.

What You Can Expect

 Improved control over how attributes and related tables are handled during duplicate CI remediation.
 Enhanced stability for large de-duplication tasks by defining thresholds and exclusion lists.
 Ability to safely test remediation scenarios without impacting production data using dry run mode.
 Options to bypass workflow-related errors to ensure remediation tasks complete successfully.

Use de-duplication properties to configure how remediation of duplicate CIs works when using the Duplicate CI Remediator, or the De-duplication Dashboard in CMDB Workspace .

To view and edit these properties, the sn_cmdb_admin or admin role is required.

Although the properties below reference the Duplicate CI Remediator, these properties have an equivalent effect in CI de-duplication experience in CMDB Workspace.

When set to false (default value), updates specified in the wizard are actually performed.

You can set this property to true and then test run through the Duplicate CI Remediator without any records actually being updated. In this case, the work notes for the task describe the changes that will

glide.duplicate_ci_remediator.merge_related_items_enhanced
Enables the capability to ignore database errors and/or skip ALL business rules (disable workflow) in related tables referencing CIs, during duplicate CI remediation. In such related tables, automated
 workflows such as business rules might prevent the update of the referenced CI to the main CI, causing de-duplication tasks to fail. In these situations, blocking business rules and other automated workflows, and
 ignoring errors allows remediation to complete.

Type: true | false

Default value: true

Location: Add to System Properties [sys_properties]
