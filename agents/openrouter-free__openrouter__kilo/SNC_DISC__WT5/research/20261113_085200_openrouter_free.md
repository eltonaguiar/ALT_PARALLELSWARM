## Key findings

1. **CI Class Manager location:** Configuration > CI Class Manager shows per-class identification rules.
2. **Identification rule types:** Derived (inherited from parent class), Independent (serial number only), Correlation ID (first matching criteria).
3. **Inclusion rules location:** Configuration > Identification/Reconciliation > Identification Inclusion Rules.
4. **Critical rule:** Do NOT use "Class" as a condition on parent tables like cmdb_ci_hardware — causes child classes to be treated as duplicates.
5. **Dependent CIs:** Require hosting rules (e.g., Kubernetes Pod identified by UID + cluster containment).
6. **IRE processing logic:** Payload validate → identification rules → CI found? → reconciliation → update/create.
